Why we are here
02 / 16

Vanilla Copilot is a generalist.
Your team needs an AGENT that knows FEV.

It doesn't know what fev_rtl2syn means, re-asks the same questions every session, and hallucinates ward paths.
Agent engineering = teaching Copilot your domain once, in files that live next to your code, so every engineer gets the same expert behavior.

Talk contract: by the end you can build a mini FEV log-triage agent from scratch. Seven primitives, one running example, real do/don'ts from the authoring handbook.

Seven primitives · one sentence each
04 / 16

Pick the smallest primitive that owns the responsibility.

Instructions

Always-on facts: vocab, invariants, path rules. Loaded when applyTo glob matches.

Skills

Reusable multi-step procedure. Auto-loaded by description match. One job per skill.

Agents

Persona + tool budget. Master routes; sub-agents specialize and return a structured result.

Prompts

One-click user recipe. User types /name, you collect inputs, delegate.

Config YAML

Living knowledge: signatures, page IDs, ward paths, MCP registry, terminology.

MCP
External tool calls

HSDES, Confluence, GitHub — real fetches with citations. Load deferred tools via tool_search.

Memory
Durable context

User · Session · Repo tiers. Stores lessons — not a substitute for citing a fresh source.

Folder names are recognized conventions. Composition happens via descriptions, not imports. Build in dependency order so every reference is valid.

Build order for this deck

Instruction → Config YAML → Skill → Sub-agent → Master → Prompt. Each references only files that already exist.

Detect the tool from the header. 2. Match signatures against the YAML catalog. 3. Build a milestone timeline.
Click a card to highlight the field
applyTo

Glob for auto-attach. '**' = every turn — only for true global facts.

description

The search key. Bad wording = silent non-use. Write it like a trigger list.

tools

Minimum needed. Research agents never see execute or write tools.

agents

Sub-agent allow-list. Limits blast radius on the master.

user-invocable

false hides from picker. Use on every specialist sub-agent.

body

Behavior. Short + structured: ## When to use, ## Procedure, ## Output Format.

File 1 of 6 · Instruction · click a card to highlight

.github/instructions/fev-domain.instructions.md
always-on primer · no dependencies
--- applyTo: '**' description: 'FEV vocabulary — always loaded.' --- # FEV domain primer - Conformal LEC log → `logs/lec.log` - Formality log → `logs/fm.log` - Run-area: `$ward/runs/$block/$tech/$flow/$task` - "Non-equivalent" = golden ≠ revised. - "Abort" = tool gave up; check the line before. - iVAR `ivar($task,guidance_file_path)` = vsdc (Conformal) or SVF (Formality).
Click to highlight
Frontmatter

applyTo: '**' auto-loads every turn. Cheap because the body is dense and short — not 800 lines of wiki paste.

Canonical log paths

Two lines. Copilot stops guessing where the log lives.

Run-area pattern

Plural runs, four variables — prevents a whole class of hallucinated paths.

FEV vocabulary

Non-equivalent, abort — exact meaning to FEV engineers, nothing to vanilla Copilot.

iVAR mapping

Which knob to inspect when guidance is missing. One iVAR, two tools.

Do

Short, exact, scoped. Use "prefer / when / unless".

Don't

Paste the wiki. Duplicate AGENTS.md. Stuff trivia behind applyTo: '**'.

09 / 16
.github/config/log-signatures.yaml
living catalog · no dependencies · read explicitly by the skill
# .github/config/log-signatures.yaml # Read explicitly by the skill. Not auto-loaded. conformal: log_file: "logs/lec.log" banner_patterns: ["Conformal", "LEC>"] milestones: - { id: mapping_done, pattern: "Mapping complete", meaning: "Key-point mapping done." } errors: - { id: non_equiv, pattern: "Non-equivalent|NEQ\\b", meaning: "Compare points differ.", correlation: "reports/ + violation_rpts/" } - { id: flatten_abort, pattern: "abort in flatten_model", meaning: "Missing UPF or guidance file.", correlation: "check ivar(guidance_file_path)" } inspect_fev: pre_waiver: "results/InspectFEV_SUMMARY.rpt" violations: "outputs/violation_rpts/"
Click to highlight
Milestones vs errors

Two separate arrays. Milestones are positive waypoints; errors each carry a correlation field naming the report to open.

Schema discipline

Every error entry: id, pattern, meaning, correlation. Treat schema changes like API changes.

InspectFEV outputs

Pre-waiver report and violation folder — the skill reads both to correlate log findings to audit results.

Do

Add entries as small PR diffs. Log-Analyzer proposes paste-ready YAML for unrecognized lines.

Don't

Hardcode evolving regexes into agent bodies. That creates hidden duplication across files.

Catalog rule: never silently ignore an unrecognized line. Always propose it as a new entry.

Folder name = name: field

Mismatch is the #1 silent skill bug. The folder fev-log-analysis/ must match exactly.

Description = discovery surface

Copilot sees only name + description first. Trigger-rich wording earns the load.

References file 2

Reads log-signatures.yaml by relative path. That file already exists — reference is always valid.

Do

Trigger-rich description. Deterministic numbered steps. Catalog referenced by relative path.

Don't

Make a prompt disguised as a skill. Inline 200 regexes. Write "use your judgment".

File 4 of 6 · Sub-agent · Log-Analyzer · click a card to highlight

.github/agents/log-analyzer.agent.md
hidden specialist · invokes fev-log-analysis skill (file 3)
--- description: 'Log-Analyzer — parses lec.log / fm.log, correlates to reports/ and InspectFEV. Triggers: "log","abort","non-equivalent".' tools: [read/readFile, search/textSearch, search/fileSearch] user-invocable: false # hidden — master calls it --- ## Inputs - run-area: $ward/runs/$block/$tech/$flow/$task - log: logs/lec.log / logs/fm.log or pasted excerpt ## Output contract (required — sub-agents are stateless) TOOL / TIMELINE / FIRST_FAIL / NEXT_STEP
Click to highlight
Trigger-rich description

The master's routing table matches against these exact words. Weak wording = missed routing.

Minimum tool budget

Read + search only. No write, no execute. Keeps blast radius small for a read-only specialist.

Hidden from picker

user-invocable: false on every specialist. One entry point visible to users.

References files 1, 2, 3

Uses vocabulary from file 1, accepts paths from the run-area pattern, invokes skill (file 3) which reads catalog (file 2).

Output contract is mandatory

Sub-agents are stateless — one prompt in, one structured answer out. Master must parse it.

Do

One role, minimum tools, explicit output format, trigger words in description.

Don't

Converse with the user. Return one result. No circular handoffs. No slash prompts.

Sub-agents ≠ prompts. Reusable multi-step logic inside a sub-agent belongs in a skill.

visible orchestrator · routes to log-analyzer (file 4)
--- description: 'FEV-Lead — entry point for FEV triage. Routes to specialists. Start here.' tools: [read/readFile, search/codebase, agent/runSubagent] agents: [log-analyzer] # allow-list — file 4 ✓ user-invocable: true --- On first turn: greet, list capabilities, then wait. On every turn: 1. Classify intent. 2. Announce which sub-agent handles it. 3. Call runSubagent("log-analyzer", "<task>"). 4. Cite result. ## Routing table "log"|"abort"|"non-equivalent" → log-analyzer
Click to highlight

Master does no real work

It routes and synthesizes. Tool budget is tiny: read, search, runSubagent.

First turn = onboarding

Greet, list sub-agents, wait. Users discover capabilities without reading any docs.

Effective capability = union

Audit master tools + all callable sub-agents' tools together.

Start with one sub-agent

Allow-list = [log-analyzer] only. Add HSD/Wiki/Ward after the smoke test passes.

Don't give the master every tool — that's the swiss-army antipattern.

File 6 of 6 · Prompt
13 / 16
.github/prompts/analyze-fev-log.prompt.md
slash command · invokes FEV-Lead (file 5)
--- mode: agent description: 'Analyze a FEV log: timeline + first failure + next step.' --- Log: **${input:log_path_or_excerpt}** Invoke `FEV-Lead` and ask it to analyze the log above using the `fev-log-analysis` skill. Render: - milestone timeline (line-numbered) - first failure block (±10 lines) - one concrete next step

A prompt is a one-click launch surface.

The user types /analyze-fev-log, provides the log, and all six files fire in sequence. They never need to know any agent or skill names.

Do

One job. Typed ${input:…} vars. Explicit handoff. Confirm before edits.

Don't

Multi-turn (use a skill). Re-implement skill inline. Grant execute when only read needed.

Prompts are user-only. Sub-agents cannot run slash prompts. Reusable sub-agent logic belongs in a skill.

Layers 6 and 7 · MCP + Memory
15 / 16

The slice gets stronger when agents can act on real data and remember.

MCP = live tool calls to source-of-truth systems (HSDES tickets, Confluence BKMs).
Memory = durable lessons across turns and sessions. Both need scope discipline to avoid bloat.

Do

Document expected MCPs in AGENTS.md. Print capability summary first turn. Cite HSD field or wiki title + URL.

Don't

Invent MCP tool names — use tool_search. Paraphrase tool results. Grant write-MCP to read-only personas.

HSDES

Ticket source-of-truth

get_hsd_article · search_hsd · skill_root_cause

Confluence

BKMs & methodology

confluence_search · get_page · get_page_children

Memory scopes

Three tiers

User · Session · Repo. Each has different persistence and intended content.

Scope discipline

Memory ≠ citation

Memory stores lessons. Always fetch a fresh page for factual answers.

Review rubric · from the authoring handbook
16 / 16

Do

  • One vertical slice before a hierarchy.
  • One user-facing agent — hide everything else with user-invocable: false.
  • Minimum tools per agent — add as real needs emerge.
  • Write descriptions: "Use when {trigger words}…"
  • Co-locate skill assets next to the SKILL.md that uses them.
  • Externalize evolving data into .github/config/*.yaml.
  • Use "prefer / when / unless" for judgment guidance.
  • Keep copilot-instructions.md under 100 lines.
  • Document MCPs in AGENTS.md; cite source fields verbatim.

Don't

  • Don't ship both AGENTS.md and copilot-instructions.md.
  • Don't add applyTo: '**' to non-essential instructions.
  • Don't build swiss-army agents — 30 tools, vague description.
  • Don't write skills that are really prompts (no steps, no assets).
  • Don't write prompts that are really workflows (multi-turn, bundled).
  • Don't mismatch skill folder name and name: field — fails silently.
  • Don't create circular handoffs with no termination condition.
  • Don't grant execute or write-MCP to research-only agents.
  • Don't paraphrase tool results — quote HSD field / wiki URL.

Two killer patterns: 
Overfit — agent hardcoded to one ward/block. Fix: inputs + YAML. 
Underfit — "you are a helpful FEV assistant." Fix: concrete nouns, hard rules, output contracts.
